## 让客房大屏可以聊，也可以帮忙

旅行中的客房大屏，可以是问一个小问题的地方，也可以是在一天行程结束后，轻松聊两句的入口。酒店 TV 智能体探索的是：让角色陪伴与实用帮助出现在同一个界面中。

选择一位管家，聊聊今天、听一段晚安故事、查看示例酒店知识库，或尝试灯光、空调、窗帘和电视状态的演示操作。语音交互之外，也保留文字输入，便于在不同环境和设备上尝试。

**当前是本地演示，不是已经部署的酒店系统。** 客房、设备状态、频道与知识库均为示例，没有接入实际酒店、PMS、真实房控或实时电视直播。它适合在开发真实集成之前，先理解和验证交互流程。

两位管家是不同对话气质的起点。你可以探索现有行为、调整角色逻辑，并设计自己的交互场景；角色介绍并不保证模型一定会按固定内容回复。

原项目人物素材按维护者要求公开展示，功能预览使用隔离演示数据。源码包默认使用占位图。应用界面目前以中文为主；顶部语言按钮切换的是项目介绍。

## 从一句话，到看得见的交互

| 试试这样的想法 | 可以探索的原型环节 |

| “我想让小姐姐陪我” | 管家选择与日常对话 |

## 功能可以怎样体验？

### 1. 大屏上的角色陪伴

人物、对白和常用操作出现在同一界面中，方便研究客人怎样在聊天、故事和实用信息之间转换。项目包括欢迎页、人物舞台与任务面板，可以作为 TV 对话交互的实验起点。

画廊保留了原管家的外观。公开代码使用可替换的占位素材，运行者可以自行加入有权使用的图片。

### 2. 语音入口与文字备用

网页提供语音交互原型与文字输入路径。语音是否可用取决于浏览器、麦克风权限和语音服务；Android 源码包含原生识别接口，便于进一步研究手机或目标设备上的表现。

语音和文字需要分别验证。文字操作成功，并不代表真实电视的麦克风、音频路由和声学识别已经通过。

### 3. 可以检查状态的房间操作

设备面板展示灯光、空调、窗帘与电视的模拟状态，让“用户提出请求—系统改变状态—界面反馈结果”这一过程更容易看见和调试。

![房间设备控制演示面板](docs/showcase/devices.jpg)

当前没有连接实际设备。若要接入真实房控，还需要设备适配器、身份鉴权、房间绑定、动作权限，以及针对具体硬件的失败处理。

### 4. 可以替换的服务知识库

后端带有本地示例知识库，可以替换为获准使用的酒店信息，再测试答案怎样检索和呈现。公开版本使用通用演示条目，不复用真实酒店地址、客户资料或私有业务文档。

这为服务问答提供了实验入口，但模型生成的答案不能自动成为酒店的真实服务承诺。

### 5. 公开信息，也可以成为聊天话题

天气与公开资讯查询可以补充旅行中的日常话题，结果受网络连接和上游来源影响。示例频道与新闻条是演示内容，不是真实新闻源或电视直播。

### 6. 把退房也作为交互的一部分

原型提供用于演示数据的退房清理动作，方便研究房间界面怎样在不同入住周期之间重置。真实使用前，仍需验证清理范围、客户端状态、会话绑定，以及多客人、多设备和失败情况下的行为。

## 适合谁继续探索？

- **开发者：** 研究 TV 界面、对话动作、本地 API 与 Android 集成。
- **酒店数字化团队：** 在开发真实酒店集成之前，评估陪伴和服务入口如何放进客房大屏。
- **开源贡献者：** 完善语音兼容、知识检索、房控适配、多语言和无障碍体验。

建议从一个小而明确的场景开始，例如一条服务问答、一次模拟设备操作，或聊天与面板之间的可靠切换。

## 开始运行

> **先下载并解压完整源码包。** 网页 Git 目录尚在整理，完整代码、构建配置和 Android 源码均在 ZIP 中。不要直接构建目前尚未齐全的网页目录。

### 运行本地网页演示

准备 **Python 3.11、Node.js 20 或更高版本**。以下命令用于 Windows PowerShell：

```powershell
Invoke-WebRequest "https://github.com/fanalar/hotel-tv-agent/raw/refs/heads/main/hotel-tv-agent-sanitized-source.zip" -OutFile source.zip
Expand-Archive ./source.zip ./hotel-source
cd hotel-source
python -m venv backend/.venv
backend/.venv/Scripts/python -m pip install -r backend/requirements.txt
Copy-Item .env.example .env
cd frontend
npm ci
npm run build
cd ..
backend/.venv/Scripts/python backend/main.py
```

打开 **http://127.0.0.1:8000**。没有模型密钥时，使用本地兜底回复与演示设备状态；需要模型对话时，在自己的 `.env` 中配置地址、模型和密钥。源码不带实际运营方凭据。

默认只监听本机。提供局域网服务需要明确调整监听配置。当前没有生产用户鉴权和房间隔离，不应直接暴露到公网。

### 探索 Android 客户端

准备 **JDK 17、Android SDK 35**，按包内 README 配好本机 SDK，在解压后的源码根目录执行：

```powershell
python scripts/fetch_android_model.py
python scripts/android_gradle.py assembleDebug
```

模型脚本从官方来源下载中文 Vosk 模型；Gradle 与依赖库另行取得。不提供预制 APK、签名材料或内置运营方密钥。服务连接在运行时配置，需要在目标设备上验证识别、权限与音频行为。

Android 源码使用 Keystore 加密保存运行时密钥。这部分仍需真机验证，也不能代替生产账号体系和访问控制设计。

## 代码如何组织？

| 组件 | 技术 | 主要用途 |
|---|---|---|
| 大屏界面 | React | 欢迎页、人物舞台与任务面板 |
| 本地后端 | FastAPI | 对话、知识、公开查询与演示设备接口 |
| 本地数据 | SQLite | 示例知识与会话记录 |
| Android 客户端 | Java | 原生客户端、识别接口与运行时设置 |
| Android 语音识别 | Vosk | 中文语音模型集成 |

代码提供的是原型交互流程，没有生产 PMS 连接器、实际房控驱动或持有授权的电视直播分发。

## 使用前常见问题

<details>
<summary>能直接接入真实酒店房间吗？</summary>

不能开箱即用。现有设备操作都是演示。真实集成需要获准使用的硬件接口、安全房间绑定、鉴权、动作权限、隐私流程和实际控制器测试，完成这些部分之后才能对外作服务承诺。

</details>

<details>
<summary>为什么预览图与第一次运行不一样？</summary>

预览副本使用原人物素材和隔离数据，并默认暂停麦克风。源码 ZIP 使用新 SVG 占位图。预览不是安装包逐像素截图，也不表示真实语音硬件已通过；素材权利另有说明。

</details>

<details>
<summary>没有模型密钥可以运行吗？</summary>

可以探索本地兜底回复、界面与模拟设备状态。模型对话和部分外部服务需要有效的配置及网络；使用自己的服务账号可能产生费用。

</details>
